# No-fallback PyJHora D1 gate — 2026-10-25

**Scope:** isolated Python 3.11 evaluation only, direct `jhora` imports; not a main-application runtime dependency, MCP server, production service, or approval to redistribute ephemeris data. No ephemeris files were downloaded. No approved ephemeris manifest or `.se1` files currently exist in the evaluation environment, so **no real Swiss-backed chart succeeded**.

## Source finding and enforcement

The isolated Python 3.11.2 environment contains PyJHora **4.8.7** and pyswisseph **2.10.3.2**. In its installed `jhora/horoscope/chart/charts.py:rasi_chart` (line 71), the D1/drik path calls `jhora/panchanga/drik.py:ascendant` (line 1722) and `dhasavarga` (line 1806). `drik.py:sidereal_longitude` (line 304) calls `swe.calc_ut` but discards its returned flag (lines 325/329). `jhora/utils.py:set_flags_for_planet_positions` (line 1714) requests Swiss; a request does **not** prove use. When `.se1` data was absent, a previous isolated probe observed `FLG_MOSEPH=4` despite requesting Swiss. The [Swiss Ephemeris programming manual](https://www.astro.com/swisseph/swephprg.htm) and [pyswisseph documentation](https://github.com/astrorigin/pyswisseph/blob/master/docs/programmers_manual/steps_to_get_a_planets_position.rst) describe the returned `calc_ut` flag as the actual selected backend. The installed `swisseph.get_current_file_data` API also exposes the `.se1` path used by a preceding calculation.

`jhora/const.py` sets the ephemeris path at import (line 267), and `jhora/utils.py:set_ephe_path` (line 417) can change it later. It is mutable library state, **not a per-call argument**. Upstream Swiss source declares the ephemeris state `TLS struct swe_data swed` ([`sweph.c`](https://github.com/astrorigin/swisseph/blob/master/sweph.c)); this indicates thread-local state in that source, but we have not independently established the exact binary build's concurrency behavior. The Python module function is monkeypatched in this probe, so the harness requires a dedicated, single-threaded process regardless. The [pyswisseph ephemeris-path documentation](https://github.com/astrorigin/pyswisseph/blob/master/docs/programmers_manual/ephemeris_related_functions.rst) says a nonempty `SE_EPHE_PATH` overrides `set_ephe_path`, and paths over 256 bytes can revert to a default; both conditions are rejected.

[`strict_pyjhora_d1.py`](strict_pyjhora_d1.py) fails before calculation unless a separate, approved manifest names every `.se1` file in the selected directory with SHA-256, byte size, source URL, source revision, rights evidence, and review/approval record. It checks the inventory again before returning. It rejects missing, unreadable, symlinked, altered, duplicate, or unlisted data. **A JSON field saying “approved” is a technical gate, not legal proof**; the rights decision must be made and recorded outside this script.

The accepted manifest keys are `manifest_version: "1.0"`, `status: "approved_for_local_calculation"`, `approved_by`, `approval_record`, `source_revision`, `rights_evidence`, and a nonempty `files` array of `name`, lowercase `sha256`, `size_bytes`, and `source_url`. No real approved manifest is supplied by this milestone.

For the audited D1 call path, the harness imports PyJHora only after data checks; verifies both installed versions and SHA-256 of four inspected PyJHora modules; explicitly sets the ephemeris path, Lahiri, sidereal planets, Swiss flags, geocentric and apparent positions; and temporarily intercepts every `swe.calc_ut` call. A request for another ephemeris, missing/unexpected actual return flag, unapproved actual `.se1` path, or missing required planet calls raises `EphemerisVerificationError` and returns no chart. The ephemeris directory is rehashed before a result is returned. Birth date/time must be valid ISO 8601 with a fixed UTC offset (or an equivalent aware `datetime`); coordinates and offset are bounded. There is no retry or alternate engine branch.

**Boundary:** `drik.ascendant` uses `swe.houses_ex` for Lagna geometry; that API does not return a planetary ephemeris-selection flag. The result labels this separately, not as an independently verified Swiss planetary calculation. This gate covers D1 planetary calls only. Panchanga, sunrise, Vimshottari, Vargas, and other PyJHora APIs have not had their full call paths/backend flags proven and are **unsupported/fail-closed** here. Source pinning limits, but cannot make this global interception safe for arbitrary third-party code or production concurrency. Astronomical accuracy and Jyotisha conventions still need independent review.
